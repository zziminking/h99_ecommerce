# K6 Heavy Spike Test 결과 보고서

## 1. 테스트 개요

### 1.1 테스트 정보
- **테스트 유형**: Heavy Spike Test (서버 한계점 테스트)
- **테스트 스크립트**: `k6/spike-test-heavy.js`
- **테스트 목적**: 급격한 트래픽 증가 시 서버 다운 시점 확인

### 1.2 테스트 설정
- **부하 패턴**:
  - 10초: VU 10명
  - 10초: VU 1000명 (급증!)
  - 3분: VU 1000명 유지
  - 10초: VU 10명 (급감)
  - 2분: VU 10명 유지 (복구 확인)
- **총 테스트 시간**: 5분 30초
- **대상 API**: `POST /api/coupons/1/issue?userId={userId}`
- **쿠폰 재고**: 10,000개

### 1.3 임계값 설정
```javascript
thresholds: {
  http_req_duration: ['p(95)<10000', 'p(99)<15000'], // Spike 상황 고려
  http_req_failed: ['rate<0.1'],                      // 에러율 10% 미만
  coupon_issue_duration: ['p(95)<10000'],             // 쿠폰 발급 95% 10초 이내
}
```

## 4. 주요 발견사항

### 4.1 핵심 발견
1. **서버는 VU 1000 부하에서도 다운되지 않음**
   - 5분 30초 동안 안정적으로 운영됨
   - 평균 3,171 RPS 처리
   - P95 응답 시간 184ms 유지

2. **높은 실패율의 원인은 재고 소진**
   - 99.90% 실패율은 서버 오류가 아닌 정상적인 "SOLD_OUT" 응답
   - 10,000개 쿠폰이 모두 소진되어 추가 요청이 실패
   - 재고 정확성은 100% 유지됨 (1,000개 정확히 발급)

3. **Redis Lua Script의 원자적 처리 성공**
   - 1,046,922건의 동시 요청 중 정확히 1,000건만 성공
   - 중복 발급 0건
   - 재고 음수 발생 0건
