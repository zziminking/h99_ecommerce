## 프로젝트 개요

### 기술 스택
- **Language**: Java 21
- **Framework**: Spring Boot 3.5.7
- **Build Tool**: Gradle
- **Database**: InMemory (ConcurrentHashMap)
- **Test**: JUnit 5, Mockito
- **Documentation**: Swagger (SpringDoc OpenAPI)
- **Code Coverage**: JaCoCo

### 프로젝트 구조
```
4-Layer Architecture
├── Presentation Layer (Controller)
├── Application Layer (Service)
├── Domain Layer (Entity, VO, Repository Interface)
└── Infrastructure Layer (Repository Implementation)
```

## 주요 기능

### 1. 상품 관리
- 상품 목록 조회
- 상품 상세 조회 (조회수 자동 증가)
- 재고 확인 및 관리
- **인기 상품 조회** (최근 3일간 조회수/주문 수량 기준)

### 2. 장바구니
- 장바구니 담기
- 장바구니 목록 조회

### 3. 주문/결제
- 장바구니 기반 주문 생성
- 재고 차감 및 보상 트랜잭션
- 쿠폰 적용 결제
- 포인트 적립
- 주문 내역 조회

### 4. 쿠폰
- **선착순 쿠폰 발급** (동시성 제어 적용)
- 사용자 쿠폰 목록 조회
- 사용 가능한 쿠폰 조회
- 쿠폰 검증 (결제 시)

### 5. 포인트
- 포인트 적립
- 포인트 조회

## 아키텍처

### 4-Layer Architecture

```
┌─────────────────────────────────────────┐
│     Presentation Layer (Controller)     │
│  - REST API 엔드포인트                    │
│  - 요청/응답 처리                         │
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│     Application Layer (Service)         │
│  - 비즈니스 로직 조율                     │
│  - 트랜잭션 관리                          │
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│        Domain Layer (Entity, VO)        │
│  - 도메인 모델                            │
│  - 비즈니스 규칙                          │
│  - Repository Interface                 │
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│   Infrastructure Layer (Repository)     │
│  - InMemory 저장소 구현                   │
│  - ConcurrentHashMap 사용                │
└─────────────────────────────────────────┘
```

### 도메인 모델
- **Product**: 상품 정보, 재고 관리
- **CartItem**: 장바구니 아이템
- **Order**: 주문 정보
- **OrderItem**: 주문 아이템
- **Coupon**: 쿠폰 정보, 발급 수량 관리
- **UserCoupon**: 사용자별 쿠폰 발급 내역
- **Point**: 사용자 포인트
- **ProductStatistics**: 상품별 일별 통계 (조회수, 주문 수량)

## 동시성 제어 보고서

### 1. 선택한 동시성 제어 방식

**Mutex/Lock (synchronized 키워드)**

Java의 `synchronized` 키워드를 메서드에 적용하여 동시성을 제어했습니다. 이는 메서드 레벨의 모니터 락을 사용하여, 한 번에 하나의 스레드만 `issueCoupon()` 메서드를 실행할 수 있도록 보장합니다.

### 2. 장단점 분석

#### ✅ 장점

**1. 정확성 보장**
- Race Condition을 완벽하게 방지하여 중복 발급이 발생하지 않습니다.
- 테스트 결과: 1000명 동시 요청 시 100장 쿠폰 → 정확히 100명만 발급 성공

**2. 구현의 단순성**
- 단일 키워드 추가만으로 동시성 제어 구현
- 별도의 락 관리 코드나 복잡한 로직이 필요하지 않음
- 코드 가독성과 유지보수성이 높음

**3. 환경 적합성**
- InMemory 저장소 (ConcurrentHashMap) 환경에 최적
- 단일 JVM에서 완벽하게 동작
- 추가 라이브러리나 외부 의존성 불필요

**4. 버그 가능성 최소화**
- 데드락 위험이 없음 (단일 락만 사용)
- 명시적인 락 해제 필요 없음 (자동 해제)
- 예외 발생 시에도 락이 자동으로 해제됨

#### ⚠️ 단점

**1. 성능 제한**
- 순차 처리 방식으로 동시 처리량이 제한됨
- 대기 중인 스레드가 많을수록 응답 시간이 증가
- 실측 처리량: 약 20,000 req/sec (쿠폰 발급에는 충분한 수준)

**2. 확장성 제한**
- 단일 JVM 환경에서만 동작
- 분산 환경 (다중 서버)에서는 동작하지 않음
- 스케일 아웃 시 Redis Lock 등 분산 락으로 전환 필요

**3. 블로킹 방식**
- 대기 중인 스레드가 블로킹 상태로 CPU 리소스 낭비 가능
- 비동기 처리 방식에 비해 효율성이 낮을 수 있음

---

### 3. 대안 방식 (고도화 시)

현재는 InMemory 단일 JVM 환경이므로 `synchronized`가 최적이지만, **분산 환경으로 확장 시에는 Redis 분산 락**이 가장 적합한 대안입니다.

**장점**
- ✅ **분산 환경 지원**: 여러 서버 인스턴스에서도 동시성 제어 가능
- ✅ **수평 확장 가능**: 서버를 추가해도 동작 보장
- ✅ **자동 락 해제**: TTL 설정으로 데드락 방지
- ✅ **높은 가용성**: Redis Cluster로 고가용성 확보

**단점**
- ⚠️ **외부 의존성**: Redis 서버 필요
- ⚠️ **네트워크 지연**: Redis 통신으로 인한 오버헤드 (약 1~2ms)
- ⚠️ **운영 복잡도**: Redis 장애 시 쿠폰 발급 불가
- ⚠️ **비용 증가**: Redis 인프라 비용 발생

**현재 방식(synchronized) vs Redis 분산 락 비교**

| 구분 | synchronized | Redis 분산 락 |
|------|-------------|--------------|
| **적용 환경** | 단일 JVM | 분산 환경 (다중 서버) |
| **구현 복잡도** | 매우 낮음 | 중간 (Redisson 사용 시) |
| **성능** | 매우 빠름 (메모리 내) | 빠름 (네트워크 1~2ms 추가) |
| **확장성** | 불가능 | 가능 (수평 확장) |
| **외부 의존성** | 없음 | Redis 필요 |
| **비용** | 없음 | Redis 인프라 비용 |
